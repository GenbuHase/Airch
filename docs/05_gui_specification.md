# GUI仕様書 (GUI UI Specification)

- **プロダクト名**: `airch ui` (Visual Architecture Dashboard & Builder)
- **対象バージョン**: 1.0.0
- **ステータス**: Approved for Roadmap
- **作成日**: 2026-09-26

---

## 1. ビジョン & コンセプト

### 1.1 背景と目的
CLIおよびYAMLマニフェスト（`airch.yaml`）は、Git管理やCI/CDパイプライン、決定論的な自動化において最も優れたフォーマットです。
しかし、大規模プロジェクトや複数チームが関与する組織においては、以下のようなニーズが発生します。

1. **アーキテクチャの直感的な可視化**:
   コードベースのレイヤー関係やモジュール境界、依存関係の健全性を、テキスト（YAML）だけでなくダイアグラムとして一目で把握したい。
2. **ノーコード/ローコードでの境界設計**:
   YAMLの構文を意識することなく、GUI上でモジュール間の「矢印（依存関係）」を繋ぎ替えるだけで境界ルールを直感的に設定・更新したい。
3. **違反箇所のビジュアル探索**:
   どのFeatureがどのEntityを不当にインポートしているのか、ネットワークグラフ上で違反ライン（赤色ハイライト）として即座に発見したい。
4. **AIコンテキストのリアルタイム確認**:
   現在の設定がAI（GPT-5.6, Claude, Cursor等）にどう伝わるかをGUI上でプレビューし、シミュレーションしたい。

`airch ui` は、**「コードとしてのアーキテクチャ（AaC）」と「視覚的なアーキテクチャモデリング」をシームレスに架橋するローカルWebダッシュボード** です。

---

## 2. 提供形態 & アーキテクチャ

開発者の導入障壁を最小化するため、まずは **CLI統合型の軽量ローカルWebサーバー** として提供し、将来的にVSCode拡張やクラウド版へと展開可能な疎結合設計を採用します。

```text
┌────────────────────────────────────────────────────────┐
│                      airch CLI                         │
│  $ airch ui                                            │
└───────────────────────────┬────────────────────────────┘
                            │ (ローカルHTTP/WebSocket起動)
                            ▼
┌────────────────────────────────────────────────────────┐
│              ローカルサーバー (Node.js / Hono)          │
│  - 静的アセット配信 (Vite SPA)                          │
│  - @airch/core API (ManifestLoader, Linter, Generator) │
│  - ファイル監視 (File Watcher -> WebSocket / SSE)       │
└───────────────────────────┬────────────────────────────┘
                            │ (localhost:4567)
                            ▼
┌────────────────────────────────────────────────────────┐
│             Webフロントエンド (airch ui)                │
│  - React 19 + Vite + Tailwind CSS                      │
│  - @xyflow/react (React Flow) による依存関係グラフ     │
│  - Monaco Editor (YAMLリアルタイム双方向同期)          │
└────────────────────────────────────────────────────────┘
```

- **起動方法**: `npx airch ui` を実行すると、ローカルポート（デフォルト: `4567`）でサーバーが立ち上がり、デフォルトブラウザでダッシュボードが自動起動します。
- **ゼロインストール**: 外部のDBやクラウドサービスへの接続は不要。ローカルのファイルシステムと完全に同期します。

## 3. 主要機能 (Core Features)

### 3.1 機能 1: インタラクティブ・アーキテクチャグラフ (Visual Dependency Graph)
モジュールやレイヤーの関係性をノードとエッジで表現するインタラクティブダイアグラム。

- **ノード表現**: 各モジュール（例: `src/features/*`, `src/entities/*`）をカード形式で表示。内部のファイル数、ルール数、健全性スコア（エラー数）をバッジ表示。
- **エッジ表現**:
  - **緑・青線**: 許可されたインポート（`allowed_imports`）
  - **赤色破線 & パルス**: 実際に発生しているアーキテクチャ違反（`forbidden_imports` 違反）
- **操作性**:
  - ノードをドラッグしてレイアウト調整（FSDの階層順、Clean Architectureの同心円状レイアウトなど）。
  - ノード間の接続ポートをドラッグ＆ドロップすることで、新しい依存許可ルールを直感的に作成可能。

```text
+-------------------+             +-------------------+
|  Features (auth)  | ----------> |  Entities (user)  |
|  [0 errors]       |             |  [0 errors]       |
+-------------------+             +-------------------+
          |                                 ^
          | (✕ 赤破線: Cross-import違反)     |
          v                                 |
+-------------------+                       |
|  Features (cart)  | ----------------------+
|  [1 violation!]   |
+-------------------+
```

---

### 3.2 機能 2: 双方向同期マニフェストビルダー (Bi-directional Manifest Editor)
ビジュアル操作と `airch.yaml` テキストがリアルタイムに双方向同期します。

- **GUI -> YAML**:
  - GUI上でモジュールの追加、命名規則のドロップダウン選択、許可/禁止パスの追加を行うと、ローカルの `airch.yaml` が自動フォーマットされて保存されます。
- **YAML -> GUI**:
  - 組み込みの Monaco Editor（または手元のVSCode）で `airch.yaml` を手動編集して保存すると、WebSocket経由で即座にGUIダイアグラムがリロード・反映されます。

---

### 3.3 機能 3: アーキテクチャ健全性ヒートマップ & 違反インスペクター (Violation Inspector)
`airch check` の結果をビジュアルに探索できるデバッグパネル。

- **ファイルツリーヒートマップ**: ディレクトリツリー上で、違反のあるファイルが赤色、警告が黄色で強調表示されます。
- **違反ディテールビュー**:
  - 違反ファイルを選択すると、該当箇所のコードスニペットと禁止インポートの行番号を表示。
  - 「なぜ禁止されているのか（アーキテクチャ原則）」と「どう修正すべきか（リファクタリング提案）」を明示。
  - ワンクリックで `--fix`（ファイル名変更やスタブ作成）を実行するボタンを提供。

---

### 3.4 機能 4: AIコンテキスト・シミュレーター (AI Context Preview & Playground)
生成されるAIルール（`AGENTS.md`, `.cursorrules` 等）がAIにどのように解釈されるかを事前に確認・調整できます。

- **リアルタイムMarkdownプレビュー**: マニフェスト編集に応じて、生成される `AGENTS.md` のMarkdownを右ペインにリアルタイム表示。
- **プロンプトテスト**: 任意のタスク指示（例:「カート画面にクーポン適用ボタンを追加して」）を入力すると、どのモジュール境界ルールが参照されるかをハイライトするシミュレーション機能。

## 4. UI/UX 画面構成

ダッシュボードは、以下の4画面（タブ）で構成されます。

| タブ名 | 用途・機能 |
| :--- | :--- |
| **1. Overview (Architecture Graph)** | モジュール境界とレイヤー構造の全体ネットワーク図、違反エッジのハイライト |
| **2. Violations (Linter Report)** | 検出された違反の一覧、フィルタリング（重要度・レイヤー別）、インライン修正 |
| **3. Manifest Editor (YAML / Form)** | フォーム形式およびMonaco Editorによる `airch.yaml` の編集・保存 |
| **4. AI Guidelines (Rule Preview)** | `AGENTS.md` / `.cursorrules` 等の生成結果プレビューとエクスポート設定 |

## 5. 技術スタック選定

| レイヤー | 技術選定 | 選定理由 |
| :--- | :--- | :--- |
| **GUI Frontend** | **React 19 + TypeScript** | エコシステムの豊富さ、型安全性、コンポーネント資産の活用 |
| **Build Tool** | **Vite** | 超高速なビルド・HMR、軽量な静的アセットバンドル |
| **Graph Visualization** | **@xyflow/react (React Flow)** | ノードベースUI・ネットワークグラフの業界デファクト。カスタマイズ性とパフォーマンスに優れる |
| **Styling & UI Components** | **Tailwind CSS + Radix UI (shadcn/ui)** | ダークモード対応、モダンで洗練された開発者向けUI、アクセシビリティ |
| **Code Editor** | **Monaco Editor (@monaco-editor/react)** | VSCodeと同等のYAML編集体験、シンタックスハイライト、スキーマ補完 |
| **Local Server / Bridge** | **Node.js Native HTTP / Hono** | 依存関係が極めて小さく、CLIバイナリに同梱可能な軽量Webサーバー |
| **Realtime Sync** | **WebSocket / SSE** | ローカルファイルの変更をミリ秒単位でフロントエンドへプッシュ配信 |

## 6. パッケージ構成 (Monorepo 構成案)

`airch ui` の追加を見据え、プロジェクト構造を疎結合なモノレポ構造（pnpm workspaces / Turborepo）として整理します。

```text
airch/
├── packages/
│   ├── core/           # @airch/core: マニフェスト解析、Linter、Generator (純粋ロジック)
│   ├── cli/            # @airch/cli: commander によるコマンドライン実行バイナリ
│   └── ui/             # @airch/ui: Vite + React による Web GUI アプリケーション
├── docs/               # 設計ドキュメント群
├── package.json
└── pnpm-workspace.yaml
```

- `@airch/core`: CLIおよびUIの双方から利用される純粋なTypeScriptライブラリ。Node.js / ブラウザ双方で動作可能な設計。
- `@airch/cli`: ターミナルから `airch` コマンドを実行するエントリポイント。`airch ui` 実行時に `@airch/ui` の静的ビルドを内蔵サーバーで配信。
- `@airch/ui`: Webアプリケーション。開発時は独立して `pnpm --filter ui dev` でHMR開発可能。

## 7. 将来の拡張性 (Future Extensions)

1. **VSCode / Cursor 拡張機能 (`vscode-airch`)**:
   `@airch/ui` のWebviewコンポーネントを流用し、エディタ内のサイドパネルでアーキテクチャグラフを表示。
2. **CI Artifact / HTML レポート生成**:
   `airch check --format html` を実行することで、静的なHTMLダッシュボード（グラフと違反レポート）を出力し、GitHub PagesやPRのアーティファクトとして閲覧可能にする機能。
